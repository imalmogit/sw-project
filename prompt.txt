I want you to act as my technical partner for this university project.
I uploaded:

* the current official project specification — this is the highest-priority and authoritative source
* files from a previous/reference project
* some supporting files/code from the course/project environment

Your job is to understand the current assignment completely and help me build a correct, working implementation.
Important rules

1. Do not start writing the full solution immediately.
2. Read the entire current project specification first.
3. Inspect all uploaded reference files and understand how the previous project was structured and implemented.
4. The current project specification always overrides the old/reference project.
5. Reuse ideas or code from the reference only when they are actually applicable to the current requirements.
6. Do not assume that the old project and current project have identical requirements.
7. Do not invent APIs, commands, file formats, libraries, inputs, outputs, or requirements.
8. If something is unclear or missing, explicitly flag it.
9. Prefer a simple, robust solution appropriate for a university course project. Do not overengineer.
10. The final result must actually be runnable/testable in the required environment.

First task — analysis only
Before implementing anything, analyze everything I uploaded and give me:
1. What this project is actually asking us to build
Explain it to me in simple terms, as if I have not followed the course closely.
2. Deliverables
Give me a complete checklist of everything that needs to be implemented and submitted.
3. Environment and setup
Tell me exactly what environment I need in order to work on this:

* operating system / VM if required
* languages
* libraries/packages
* tools
* build/compile commands
* run commands
* any setup files or configuration

If the specification does not clearly say something, distinguish between:

* explicitly required
* inferred from the reference project
* your recommendation

4. Reference project analysis
Explain which parts of the old/reference project appear relevant to the current assignment.
Identify:

* code/files that can probably be reused
* code that needs modification
* code that appears irrelevant
* important differences between the old project and the current specification

5. Proposed structure
Show me what you think the final project directory/file structure should look like and briefly explain the role of each important file.
6. Implementation plan
Break the work into small, logical stages.
For each stage include:

* what we will implement
* what files will be created/modified
* how we will test it
* what output/result will prove that the stage works

Order the stages so that we can get a minimal working version as early as possible, and then improve it incrementally.
7. Risks / unclear points
Tell me now if you see anything that could cause problems later, including missing files, unclear requirements, dependencies, environment issues, or assumptions made by the old project.
Very important
Do not dump a large amount of code yet.
I want to understand the project structure first and make sure we are solving the correct problem.
At the end, give me a section called:
"What I should do right now"
with the first 3–5 concrete actions I should take on my computer.
Then stop and wait for me before starting the implementation.
